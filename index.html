01 · SYSTEM MAP

System Architecture Map

Headless topology: decoupled storefront/admin heads over a domain-service mesh with an event backbone.

↓ unidirectional flow · CQRS reads via projection cache · writes via command bus ↓

Communication Patterns

  • • Sync: GraphQL BFF per head (storefront / admin / vendor).
  • • Async: Event bus (Kafka/NATS) for RFQ state, audit, bulk jobs.
  • • Realtime: SSE channel for bulk-op progress + RFQ updates.
  • • Search: OpenSearch projection for specs matrices.

Cross-Cutting Concerns

  • • API Gateway → authN, tenant resolution, rate-limit.
  • • Policy Engine (OPA/Casbin) → Micro-RBAC field masking.
  • • Audit interceptor → immutable append-only log.
  • • Idempotency keys on all mutating endpoints.

Tenancy Model

  • • Row-Level Security via tenant_id on all vendor tables.
  • • Shared schema + RLS policies (pooled multi-tenant).
  • • Per-vendor object-storage prefix isolation.
  • • Buyer org = sub-tenant with its own user graph.
02 · DATA LAYER

Database Schema — High-Level Logic

Domain-aligned aggregates. Every vendor-scoped table carries tenant_id enforced by RLS.

Key Relationships & Invariants

• rfq 1—N sub_rfq (one per vendor) → solves multi-vendor deadlock.
• product.status ∈ {draft, in_review, published, archived}.
• role_field_policy drives runtime field masking (Micro-RBAC).
• audit_log is append-only, hash-chained (prev_hash).
• impersonation_session stores actor + subject + scope caps.
• bulk_job → N bulk_job_item streamed via SSE.
